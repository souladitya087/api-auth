## 2. Vulnerability Findings & Reproduction

### 1. [CRITICAL] Broken Object Level Authorization (BOLA) in /api/v1/documents/{doc_id}

- **Endpoint:** `GET /api/v1/documents/{doc_id}`
- **Standard:** `API1:2023 - Broken Object Level Authorization`
- **Vulnerability Class:** `BOLA`

**Description:**  
User 'User_B (Bob)' was able to access or modify resource {'doc_id': 'doc_101'} belonging to 'User_A (Alice)' via GET /api/v1/documents/{doc_id}. Server returned HTTP 200.

**Reproduction (cURL):**
```bash
curl -X GET http://127.0.0.1:8000/api/v1/documents/doc_101 -H 'Authorization: Bearer token-bob-456'
```

**Remediation Guidance:**  

Validate that the authenticated requester possesses explicit ownership or tenancy over the requested object identifier in database queries. Example: `SELECT * FROM items WHERE id = :id AND owner_id = :auth_user_id`.

### 2. [HIGH] Broken Function Level Authorization on Admin Endpoint (/api/v1/admin/system-stats)

- **Endpoint:** `GET /api/v1/admin/system-stats`
- **Standard:** `API5:2023 - Broken Function Level Authorization`
- **Vulnerability Class:** `BFLA`

**Description:**  
Standard user 'User_A (Alice)' successfully invoked administrative endpoint GET /api/v1/admin/system-stats receiving HTTP 200. Role-Based Access Control (RBAC) was not enforced.

**Reproduction (cURL):**
```bash
curl -X GET http://127.0.0.1:8000/api/v1/admin/system-stats -H 'Authorization: Bearer token-alice-123'
```

**Remediation Guidance:**  

Implement role-based authorization checks (e.g., verifying user.role == 'ADMIN') at the route guard or middleware level before executing administrative operations.
